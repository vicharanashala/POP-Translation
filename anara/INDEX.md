# anara: index

Standalone local test: do chunk embeddings find the right document and page for a query?
Nothing here imports `dashboard/`. Run everything with `.venv/bin/python3 anara/<script>`.

## Decisions
- Embedding model: `BAAI/bge-small-en-v1.5` (English, CPU, 384 dims). Not multilingual-e5.
- Source: `pop-documents-state-2026-11-12.xlsx` (709 Punjab placements, 533 unique documents).
- Original PDFs are used (no document is translated); only English-text ones are embedded.
- Mongo: the user's own Atlas account (not yet created). Collections `unique_documents`, `doc_embeddings`.
- Pause and tell the user at ~300k context.

## Crop-zone mode (mode=zone) status
- Built `python anara/zonesearch.py build` (3 s). Zone parameters (SMOOTH, SEED_FRAC, MIN_CROP, STOP_RUN, COVER, MAX_SPAN) are my choices, tuned by eye on the Kharif POP only.
- Zones vs known Kharif POP chapters: sugarcane 17/19 pages, maize 12/13, groundnut 4/5, cotton 11/17, paddy 0/14 (paddy's heading chapter scores below rival crops, so its zone is the later p26-31 basmati section).
- Known answers hit: pink bollworm p65 (expected 56-68), foot rot p29 (expected 27-32). Top-1 agreement with the embedding search is 4/11, mean top-3 overlap 1.1/3; agreement is not accuracy. A query with no crop-master crop returns nothing (no fallback).
- Heading-start zones (replacing score-only starts where a heading exists): Kharif POP labelled chapters covered 68/68 pages (score-only zones: 44/68), 14 pages outside the labelled ranges (paddy's range 11-24 was a rough guess and the zone runs to 35). The rules were tuned on this one guide; the Rabi POP (not tuned on) gave sensible starts and ends by eye. Heading zones answer wheat in 38 of 46 documents with a zone, paddy 39/55, cotton 14/24, maize 25/33, mustard 11/12, sugarcane 18/21, potato 19/20; the rest fall back to scores.
- Known gaps: a heading that is a bare ambiguous word ("GRAM") matches no unique crop (chickpea query in the Rabi POP found no zone); "Tobacco" scored as a rival inside the cotton chapter because of tobacco caterpillar (a pest name), so the BM25 end rule is used only when no chapter heading follows.
- Page-sharing rule: a chapter heading in the top 30% of its page owns the page; lower down, the page stays with the EARLIER chapter (a zone ends on it, the next one starts on the following page). Needed because index and zones are per page.
- Ranking: groups covered, then shortest stretch, then zone quality = crop's mean smoothed score over the zone x sqrt(zone length, capped at 25), then keyword BM25 strength. Zone length alone rewarded a "wheat" zone that ran 74 pages to the end of a Kharif guide; this version put the target guides (Kharif guides for 3 queries, Rabi guides for 2 wheat queries) on top for all 5, but it was chosen after seeing those 5 queries. Top-1 agreement with the embedding search is low (see compare_zone.py); agreement is not accuracy.

## Vector storage and quantization (measured on the 28,155 chunks, M0 cluster)
- The app's collection stores each of the 384 numbers as a BSON double (8 bytes; the model gives float32, `embedder.py` widens it with `float(x)`), plus ~5 bytes of per-element array overhead: 4,895 B per vector, 5,912 B per chunk. As a float32 blob a vector is 1,538 B, a chunk 2,568 B.
- `doc_embeddings_bin` (kept, app unchanged): data 72.3 MB, on disk 54.1 MB, versus 166.5 / 181.9 MB. Decoded numbers equal the originals (max difference 0.0).
- 112 queries (12 hand-written + 100 made of 14 words from the middle of random chunks, fixed seed), pool 500, numCandidates 5000, compared with exact cosine over all chunks:
  - today (doubles): recall@10 0.983, recall@500 0.999, doc top-1 0.875. Blob float32, no quantization: 0.979 / 1.000 / 0.902 (same data, different ANN graph: this is the noise floor, ~10% of queries change top-1 doc).
  - scalar quantization: recall@10 0.948, recall@500 0.962, doc top-1 0.848, only 78.6% same top-1 doc as today's index. Measurable loss.
  - binary quantization: recall@10 0.981, recall@500 0.889, doc top-1 0.902, 89.3% same top-1 doc as today's index, score error 0 (scores are exact, so the stored full vectors are probably used to rescore). The pool's tail shrinks (recall@500), the top does not.
- Not tested: 1M chunks (recall usually falls as an index fills), real user questions, index RAM size.
- Zone mode group rule: a document needs 75% of the query keyword groups OR 4 groups, whichever is fewer (`NEED_CAP` in zonesearch.py, API `need_cap`, 0 = no cap). It only changes queries with 6+ groups (7 groups: need 6 -> 4, 7 -> 18 documents; 8 groups: 4 -> 6 documents); top-1 stayed the same on all 7 tested queries.
- Zone mode fallback (`_no_zone_docs`): a document with NO zone for the query crop is searched on pages outside every crop zone (`covered_pages`, zones of all crops, cached per document), with the crop counted as one more keyword group; it needs 75% of the groups (crop included) or 4, whichever is fewer. These results follow the zone results, ranked by proximity (`tightest_stretch`: fewest pages holding that many groups, then more groups, then strength). The crop word is REQUIRED in the stretch (`tightest_stretch(..., required=)`) and also counts towards the 75%/4 rule. Making it required removed documents that matched without the crop word: on 3 long queries, 12 of 19, 21 of 28 and 5 of 25 optional-crop fallback results lacked it. `tightest_stretch` matches a brute-force check on 3,000 random cases. Proximity is in whole pages, so ties are common and an index or contents page holding all keywords ranks like a real answer. Fallback adds ~0.2-0.7 s. Pink bollworm in cotton: 12 zone + 6 no-zone documents; yellow rust in wheat 14 + 7; seed rate for maize 18 + 14; pod borer in chickpea 2 + 0. Known answers unchanged (Kharif guide rank 5 of 18 and rank 1 of 19).
- No-crop queries: if the query has no crop of the crop master (e.g. plain "mango": the master only has Green Mango, Mango Ginger, Mangosteen), zone mode no longer returns nothing; it runs the keyword-only proximity search over all pages (75% of groups or 4), no required word. "How to grow mango?" now returns the Fruit Crops POP first (p9).
- Best-effort pass (`search_zone(relaxed=)`): when no document meets the threshold (zone and no-zone together), the search reruns with no minimum and returns up to 10 documents ranked by most keyword groups, then fewest pages (zone before no-zone on ties); `passed` False, `keywords.relaxed` True, page shows an amber notice. Barley "black powdery material comes out of ears..." now returns the linked Rabi POP 2025-26 first (stretch p33-34, 3 of 6 groups); before: nothing. It missed because the PDF says "dark dusty spore mass" / "black compact mass of spores", not powdery/material/comes.
- page.html `kwHtml`: the zone banner is chosen by `!k.used` (zone mode has no `used`), not by `k.crop`; a query with no crop made the page read `k.used` and throw "Cannot convert undefined or null to object". The no-crop and best-effort modes had only been checked through the API before; they are now checked in the page.

## Auth and exposure (login, JWT, tunnel)
- `auth.py`: users in `data/users.json` (scrypt hashes, mode 600), HS256 JWT signed with `data/jwt_secret`, access token 15 min + refresh token 7 days in HttpOnly / SameSite=Strict / Secure cookies (`Authorization: Bearer` also accepted). Refresh tokens are single use; their sha256 sit in `data/refresh_tokens.json`; reusing a spent one (after a 5 s grace for two tabs) revokes the whole family. Cookie-authenticated POSTs need an `X-Requested-With` header; `/auth/*` POSTs always do.
- Every route requires a login except `/login`, `/health`, `/auth/login|refresh|logout`. Roles: viewer = GET only; admin = anything else (`/api/test/run`, `/api/test/cancel`). `/docs`, `/redoc`, `/openapi.json` are off. Pages get a CSP nonce (`auth.page`), the fetch wrapper that refreshes on 401 and the `#logout` handler are injected into `page.html`, `report.html`, `docs.html`.
- Limits (re-audit fixes): a failure slot is reserved under a lock before the password check (parallel guesses cannot pass the limit); 5 failures per (user, IP) pair or 20 per IP -> lock 15 min, doubling on repeats up to 4 h; IPv6 keyed by /64; never a lock on the username alone (against one user from many IPs only a soft limit of 1 try per 3 s applies, and IPs with a live session of that user are spared); 4 password checks at once; failure tables capped at 50,000. Expensive routes (`/api/search`, `/groups`, `/known`, `/link`, `/random_question`, `/docs/export`, `/test/report`): 30 per user per minute (`AUTH_API_RATE`), 2 running per user, 6 in all, 60 s timeout (504); all `/api`: 300 per minute (`AUTH_API_RATE_ALL`); `q` max 500 characters, `k` max 100; 64 KB bodies. Host header allow-list: localhost, `AUTH_ALLOWED_HOSTS`, lines of `allowed_hosts.txt` (re-read on change), `AUTH_ALLOWED_HOST_SUFFIXES` (opt-in). Tokens carry a version (`tv` in users.json): replacing a user (`adduser`) kills its old sessions; `genusers --force` also replaces the signing key. A refresh refused inside the grace window no longer clears the cookies. The login `next` is validated in `login.html` (tabs/newlines stripped, `new URL` origin check) and in `auth.safe_next`.
- Users: `.venv/bin/python3 anara/auth.py genusers` (admin, viewer1, viewer2; passwords once in `data/initial_passwords.txt`), `AUTH_PASSWORD=... .venv/bin/python3 anara/auth.py adduser <name> <admin|viewer>` (replaces the password of an existing name).
- Local: `AUTH_COOKIE_SECURE=0 .venv/bin/python3 anara/app.py` and open http://localhost:8050 (a Secure cookie is not sent over plain http by every browser). Public: use the container and its tunnel (next section); no tunnel program runs on the host.
- Other env: `AUTH_ACCESS_TTL`, `AUTH_REFRESH_TTL`, `AUTH_REFRESH_GRACE`, `AUTH_API_RATE`, `AUTH_ALLOWED_HOSTS`.


## Public container (keyword modes only; see docker-compose.yml, deploy.sh, expose.sh)
- Why: the host instance runs as the owner's account (docker/sudo groups, SSH agent, `.env` files). The public instance runs in Docker instead: `app` (python 3.12-slim + numpy/scipy/pandas/scikit-learn/fastapi/uvicorn/PyMuPDF/pymongo, 558 MB, code copied in) as UID 10001 with no groups, `read_only`, `cap_drop: ALL`, `no-new-privileges`, 4 GB / 2 CPUs / 256 pids, on an `internal` network with `inhibit_ipv4` (no route out, no host-side address: it cannot reach the host's localhost or LAN services or the internet), and `proxy` (nginx-unprivileged, read-only, cap-dropped) on the internal and an edge network, the only published port, `127.0.0.1:8050` (slow-client timeouts 10 s, 8 KB header buffers, 64 KB bodies, 20 connections / 20 req/s per client address).
- Mounts: `deploy/data` read-only (hard links, no extra disk, made by `./deploy.sh sync-data`, 19 files + `pagetext/`, no secrets, no PDFs, no backups); volume `anara_runs` (test results; seeded with the 39 earlier runs) and volume `anara_auth` (users.json, jwt_secret, refresh_tokens.json, allowed_hosts.txt). No `.env`, no `~`, no SSH agent, no docker socket. `ANARA_NO_DOTENV=1` makes common.py skip both `.env` files.
- Embedding modes (full, hybrid, restrict) are off (`ANARA_KEYWORD_ONLY=1`): no torch, no MongoDB credentials in the container. `/api/modes` says `available: false` for them, the page disables them, search / groups / test-run answer 503 with a message. All 9 keyword modes, random question, known question, link lookup, documents, report and labelled test runs work.
- Commands (from anara/): `./deploy.sh sync-data`, `build`, `init` (creates the container's OWN users, not the host's), `up`, `down`, `status`, `logs`, `show-passwords` (YOU run it: prints them to your terminal; then `forget-passwords`). The host instance and the container share `127.0.0.1:8050`: stop one before starting the other. Public: `./deploy.sh up`, then `./deploy.sh tunnel-up` (or `anara/expose.sh`, which does both).
- Env knobs: `ANARA_DATA`, `ANARA_RUNS`, `AUTH_DIR`, `ANARA_HOST`, `ANARA_FORWARDED_ALLOW_IPS`, `ANARA_THREADS` (8), `AUTH_HEAVY_TIMEOUT`.

### Cloudflare quick tunnel (container `tunnel`)
- `./deploy.sh tunnel-up` runs the pre-flight (`expose.sh preflight`: /health ok, app container read-only/non-root, /api/modes 401 without login, users file mode 600), starts the `tunnel` service (`cloudflare/cloudflared:2026.11.2`, `tunnel --url http://proxy:8080`), reads the random `*.trycloudflare.com` host from its logs and writes ONLY that host to `allowed_hosts.txt` (auth volume; the app re-reads it, no restart). `./deploy.sh tunnel-down` stops it and empties the file; `tunnel-status` shows both.
- Networks: `anara_internal` (app + proxy, no route out), `anara_edge` 172.29.251.0/24 (proxy + tunnel at the fixed address 172.29.251.10, outbound internet for the tunnel). The tunnel container is uid 65532, read-only, cap_drop ALL, no-new-privileges, no mounts, no published port. Docker cannot filter its egress without iptables, so it can reach the internet and anything else on the edge network (only the proxy listens there); the host's gateway ports 22/5432/6379/9222/8050 were closed when tested from that network. The proxy still publishes 127.0.0.1:8050 for local checks (loopback only).
- Client IP: nginx uses `CF-Connecting-IP` only when the TCP peer is 172.29.251.10 (`set_real_ip_from`), otherwise the TCP peer, and hands the app one `X-Forwarded-For`. Cloudflare's edge rejects a client-sent `CF-Connecting-IP` (error 1000); a spoofed `X-Forwarded-For` is ignored.
- Quick tunnel limits (Cloudflare docs): no uptime guarantee, 200 in-flight requests (more get 429), no Server-Sent Events (the app uses none), the URL changes at every start, and anyone with the URL reaches the login page.
- Tunnel hardening (follow-up): nginx and cloudflared are pinned by digest in `docker-compose.yml` (nginx 1.31.7 is the newest published nginx-unprivileged alpine tag seen; no 1.31.10 tag exists); cloudflared runs with `--metrics 127.0.0.1:20241`, so its metrics page is no longer reachable from the edge network. `deploy/firewall.sh` (run by the owner with sudo, not run by the stack) blocks the edge subnet from private ranges and from the host itself via DOCKER-USER and INPUT; not persistent across reboots. Not yet applied.
